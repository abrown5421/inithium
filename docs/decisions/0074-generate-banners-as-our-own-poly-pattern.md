# 0074. Generate banners as our own low-poly pattern in a PolyBanner composite, and store profile images as an asset or a recipe

## Context

[0027](0027-store-profile-data-in-a-user-profile-subdocument.md) planned profile banners generated by Trianglify. Trianglify is no longer maintained, so we draw the same kind of low-poly pattern ourselves, as a UI composite users can edit. Everything else in 0027 stands and is restated here.

## Decision

**Profile data** (unchanged from 0027):

- Profile data lives in a `profile` subdocument on the user, kept separate from authentication fields (`passwordHash`, `role`, etc.).
- An avatar or banner is stored as one of two things:
  - a **generator recipe**, from which the frontend renders the image: Dicebear's style or options plus a seed for avatars, a poly pattern recipe (below) for banners;
  - an **asset id** for an uploaded image ([0028](0028-store-assets-behind-pluggable-storage-drivers.md)).
  The rendered image is never stored.
- When an image is missing or fails to load, it falls back to the generated version.
- The image-with-generated-fallback shape and its component are core building blocks that plugins can reuse for their own documents, e.g. blog post banners, staff member cards and product images.
- The fields are added when the profile feature is built, not before. Users without a `profile` get a generated default.

**The poly pattern** (new):

- **Recipe:** `polyPatternSchema` in `@inithium/shared-contracts`: `cellSize` (25–250px, default 75), `variance` (0–1 in steps of 0.05, default 0.75), `xColors` and optional `yColors` (1–8 stops each, a theme or Tailwind colour at an intensity; `yColors` defaults to `xColors`) and a `seed`.
- **Drawing:** a grid of `cellSize` cells reaching one cell past each edge; each point moves up to half a cell × `variance`, from a random number derived from the seed and the point's place in the grid. Each cell splits into two triangles along the diagonal a Delaunay triangulation would pick (a seeded coin toss on a tie). A triangle's colour is the x gradient at its centre mixed half and half with the y gradient. No outlines, sparkle or shading.
- **Same everywhere:** the same recipe draws the same pattern every time. It's drawn at the banner's real size, so a wider banner shows more of the same pattern rather than a different one; the gradients stretch to fit.
- **Live colours:** an SVG whose fills mix theme variables with CSS `color-mix`, so a re-brand or dark mode recolours saved banners.
- **PolyBanner** (`@inithium/shared-ui-composites`): `value` / `defaultValue` / `onChange` (the recipe), `width` (default `'full'`) and `height` (default 200), min/max sizes, radius, margin, animation, `children` drawn over the pattern, and `label` (otherwise decorative).
- **Editing:** with `editable`, a pencil button in the top-right corner (filled surface 900, with a tooltip) opens a Modal ([0065](0065-open-modals-by-id-from-global-state.md)): a live preview in the banner's shape, Cell size and Variance Sliders, AutoIncrementingLists ([0070](0070-grow-and-shrink-lists-one-row-at-a-time.md)) of ColorPickers ([0069](0069-pick-colours-from-swatches-and-an-intensity-slider.md)) for each gradient, a "Same as X colours" Switch, and Shuffle (a new seed), Cancel and Save. Changes stay in a draft until Save, which calls `onChange`.

## Alternatives considered

- **Trianglify:** no longer maintained.
- **Colours fixed at intensity 500:** can't make light-to-dark gradients; stops take any intensity, starting at 500.
- **Baked-in hex colours:** wouldn't follow a re-brand or dark mode.
- **Drawing to a fixed size and stretching:** cells would change shape with the banner's.
- **Storing the rendered image:** unnecessary, since the pattern is deterministic. The recipe is a few bytes.
- **Adding empty profile fields now:** rejected. Their exact shape would be a guess, and MongoDB needs no migration to add fields later.

## Consequences

- Generated avatars and banners need no file storage at all.
- Uploaded profile images depend on the storage driver's capabilities: see [0028](0028-store-assets-behind-pluggable-storage-drivers.md).
- The profile feature stores a `polyPatternSchema` recipe for each banner and renders it with PolyBanner.
